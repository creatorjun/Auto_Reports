## 범위와 방법

## 유지한 경계

- Jira JQL은 저장된 보고서의 조회 근거와 사용자 기능 계약이므로 전면 추상화하지 않았습니다. 외부 필드 ID와 원시 JSON 매핑은 바깥에 둡니다.
- Pydantic 검증, HTTP 쿠키·오류·파일 응답과 HTML 이메일은 입출력 어댑터 책임입니다.
- 보고서 갱신 시 AI 총평 stale 판정은 개인정보 억제 후 실제 저장 JSON과 잠근 행을 비교하는 원자적 데이터 일관성 처리로 유지합니다. 이 비교를 요청 시점으로 옮기지 않습니다.
- 스냅샷 저장·잠금·암호화와 PostgreSQL/SQLite 트랜잭션은 Infrastructure에 유지합니다. 내부 계층에 SQLAlchemy나 HTTP client를 전달하지 않습니다.
- 공개 API, 보고서 저장 필드, DB migration, 배포 설정과 알림 수신자는 변경하지 않습니다.

## 검증과 운영 확인

`tests/test_architecture.py`는 역방향 import, core 외부 의존성, HTML 레이아웃, 공급자 payload 및 `cf[n]` ID, 외부 계층의 유스케이스 생성, 위젯 조립, HTTP 직접 작업 제출과 주석 규칙을 검사합니다.

Windows 기본 환경에서 1,032개 테스트를 실행해 통과했습니다(격리 DB·POSIX 전용 50개 제외). 이후 추가된 취소·캐시 수명 회귀까지 포함한 Python 3.11 Linux 및 격리 PostgreSQL 전체 검사는 1,038개 모두 통과했습니다. 새 DB에 migration `0024`까지 적용하고 저장소 테스트를 실행했으며, `compileall`과 diff 공백 검사도 통과했습니다.

운영 보정 스크립트 호환성 검사 1개 추가 후 관련 쿼리·아키텍처 검사 33개가 통과했습니다.

운영 검증은 별도로 이미지·health·migration, DB와 환경 보존, 실제 로그인 상태에서 보고서·SLA·보안 뉴스·Jira 알림 조회를 확인합니다. 테스트 결과와 배포 완료 여부는 실행 기록으로 구분합니다.
