# SLA 현황

`집중 관리 항목`의 메뉴 순서는 **SLA 현황 → SLA 위반 → 재배포 현황**입니다. `/sla-status`는 현재 위반 임박 티켓이며, 기존 `/sla-violations`는 SLA 위반 보고서와 히스토리 경로를 유지합니다.

## 조회 기준

진행 중인 Jira SLA 주기의 `remainingTime.millis / goalDuration.millis`가 **30% 미만**인 항목을 조회합니다. 정확히 30%인 항목은 포함하지 않습니다. 목표가 양수이고 잔여 시간이 0 이상이어야 하며, Jira가 이미 위반으로 표시했거나 음수 잔여 시간을 가진 티켓은 제외합니다. 같은 티켓의 다른 SLA 또는 완료 주기에 위반 이력이 있는 경우에도 전체 티켓을 제외합니다. 라이선스 유형과 Done 상태 범주는 제외합니다.

일시정지된 SLA도 잔여율 조건에 맞으면 포함하고 일시정지 상태를 명시합니다. 일시정지·휴일·근무시간 정책이 반영된 Jira 계측값을 표시하며 브라우저의 현재 시간으로 잔여 시간을 감소시키지 않습니다. 잔여 0이더라도 Jira의 위반 표시가 아직 false라면 임박 항목으로 포함합니다.

한 티켓에 조건을 충족하는 SLA가 여러 개 있어도 목록과 전체 티켓 수에서는 한 번만 셉니다. SLA 단계 수는 별도로 셉니다. 진행 중 SLA와 일시정지 SLA가 함께 있으면 두 요약 범위에 모두 속할 수 있습니다. 기본 정렬은 잔여율이 작은 순입니다.

기존 일일 알림은 30% **이하**의 발송 기준을 유지합니다. 이 페이지 조회·새로고침은 메일을 발송하지 않으며 SMTP와 알림 수신자 설정이 없어도 사용할 수 있습니다.

## 화면과 시간 해석

요약 카드·검색·상태·SLA 단계 조건으로 목록을 좁히고, 잔여 시간과 잔여율, 현재 상태와 담당자를 비교합니다. 티켓을 펼치면 SLA 목표·사용·잔여 시간과 고객·담당 정보 및 상태별 체류시간을 확인할 수 있습니다.

상태별 체류시간은 기존 SLA 위반 페이지의 **해결시간 SLA clock** 계산을 공유합니다. 상태 이력과 Jira 근무시간 달력으로 해결 SLA 실행 구간을 계산하며, 일시정지 상태와 닫힘 등 기존 제외 기준을 유지합니다. 생성부터 현재까지의 달력 경과시간을 SLA 체류시간으로 대신 표시하지 않습니다. 이력이나 달력을 검증할 수 없는 경우 체류시간을 확인 불가로 표시하고 경고를 제공합니다. SLA 목표와 잔여 값이 유효하면 체류시간 확인 불가만으로 티켓을 숨기지 않습니다.

프로젝트별 **마지막 성공 조회 스냅샷**을 DB에 저장합니다. 페이지를 다시 열거나 서버를 재시작해도 저장된 현황을 먼저 표시하고, 새로 수집하는 동안에도 목록과 필터를 유지합니다. 수집 시각을 함께 표시하며 자동 카운트다운으로 간주하지 않습니다. 저장된 SLA 위반 보고서의 선택 기간·히스토리와 별개입니다. 상세 수집 전에 완료되거나 접근할 수 없게 된 티켓은 결과에서 제외합니다.

## API와 자원 관리

`GET /api/v1/sla-status`는 기존 보호 라우트 인증을 사용하며 `Cache-Control: no-store`를 반환합니다. 최초 조회에서 DB 저장본을 복원하고, 저장된 시각으로부터 60초가 지났으면 기존 결과를 즉시 반환하면서 백그라운드에서 갱신합니다. `?refresh=true`는 60초 경과 여부와 관계없이 갱신을 시작합니다. 동시에 들어온 요청은 하나의 수집 작업을 공유합니다. 브라우저는 갱신 중에만 2초 간격으로 일반 조회를 실행하며 완료된 결과로 목록을 교체합니다.

전체 수집·저장의 제한 시간은 110초입니다. 아직 저장본이 없으면 최초 수집 완료를 기다리고 실패 시 503을 반환합니다. 저장본이 있는 상태에서 갱신이 실패하면 기존 결과와 오류 안내를 유지하며 60초 동안 자동 재시도를 지연합니다. 사용자가 새로고침하면 즉시 재시도합니다. 수집 실패를 0건 성공으로 표시하지 않습니다.

응답은 `generated_at`, `threshold_percent`, `ticket_count`, `sla_count`, `tickets`와 `refresh_in_progress`, `stale`, `refresh_error`입니다. 각 티켓의 `slas`에는 SLA 이름·목표 밀리초·잔여 밀리초·잔여율·일시정지 상태가 있으며 상세에는 상태별 시간과 데이터 경고가 포함됩니다. 계정 ID와 내부 개인정보 수집 메타데이터는 공개 응답에 포함하지 않습니다.

SLA 필드 탐색과 미완료 티켓 수집은 기존 알림 수집 어댑터를 재사용하고, 조건에 맞는 티켓만 추가로 이력·달력·담당 정보를 조회합니다. 상태별 시간 계산과 상세 수집기는 SLA 위반 보고서와 공유합니다. 컨테이너가 수집기와 백그라운드 작업의 종료를 관리하며 개인정보 캐시 초기화 시 진행 중 작업과 메모리 스냅샷도 초기화합니다.

마이그레이션 `0021`은 `sla_status_snapshots` 테이블을 생성합니다. 프로젝트별 최신 성공 결과 한 개만 보관하고 이전 시각의 수집 결과가 최신 결과를 덮어쓰지 못하게 합니다. 저장·복원 모두 개인정보 처리와 같은 DB 잠금을 사용하며, 삭제 대상 이름과 갱신된 프로필을 반영한 결과만 반환합니다. 계정별 개인정보 수집·갱신·삭제 대상에도 저장본을 포함합니다.
