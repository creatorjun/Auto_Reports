# backend/docs/09_redeployment_report.md

# 재배포 현황 보고서

`집중 관리 항목` 아래 첫 번째에 `재배포 현황` 메뉴(`/redeployments`)를 표시합니다. 최신 저장본을 즉시 읽고, 화면이 열려 있으면 60초마다 최신 저장본을 확인합니다. 카드의 전체·완료·진행 중 선택은 원인 분포와 목록에 적용되며, 원인 클릭 및 검색으로 상세 티켓을 좁힐 수 있습니다. 월별 그래프의 월을 클릭하면 배포 완료 월이 일치하는 완료 티켓으로 목록을 좁히며, 원인·검색 조건도 함께 적용됩니다. 선택한 월을 다시 클릭하거나 월 필터의 해제 버튼을 누르면 이전 범위로 돌아갑니다. 전체·완료·진행 중 범위를 직접 바꾸면 월 필터를 해제하고 목록의 페이지를 초기화합니다. 월별 그래프의 건수와 상단 전체 지표는 누적 현황을 유지합니다.

## 집계 계약

TACEA의 재배포 여부가 Y인 티켓에서 라이선스 유형을 제외합니다. 완료는 `Closed`이고 해결일이 2026-01-01 이후인 티켓입니다. 생성일이 2025년인 티켓도 포함합니다. 진행 중은 현재 닫히지 않은 재배포 Y 티켓 전체이며 생성일 제한이 없습니다. 이는 완료 통계와 분리해 표시합니다. 상태·원인·사유·담당 정보는 보고서 생성 시점 기준이며 과거 이벤트를 추정하지 않습니다.

Jira 대시보드 11218 분석에서 확인한 필드를 사용합니다.

| 의미 | Jira 필드 |
|---|---|
| 재배포 여부 | `customfield_11819` |
| 재배포 원인 | `customfield_11885` |
| 상세 사유 | `customfield_11852` |
| 배포 완료 월 | `customfield_12421` |
| 재패치 횟수 | `customfield_11753` |
| 고객사명 | `customfield_11022` |
| 파트너사 Assets | `customfield_10859` |

월별 완료는 위 완료 코호트의 배포 완료 월 입력값으로 분류합니다. 해결월로 대체하지 않으며 미입력·범위 밖 값은 제외 건수를 표시합니다. 재패치 횟수는 기록된 값의 합계로서 실제 배포 이벤트 수와 다를 수 있습니다. 미입력과 0은 구분합니다. 파트너 미지정은 본사, Assets 조회 실패는 이름 확인 불가로 표시합니다. 원인과 담당 정보로 책임 소재를 추정하거나 Rovo를 호출하지 않습니다.

## 자동 생성 및 보존

APScheduler가 매일 **08:00 Asia/Seoul**에 갱신합니다. 다른 보고서의 `SCHEDULE_CRON` 또는 `TZ` 설정과 독립적입니다. 시작 직후 동일 작업을 실행하되 최근 도래한 08시 이후 저장본이 있으면 Jira 재수집을 생략합니다. 중지 중 놓친 일별 보고서는 소급해서 만들지 않고 현재 시점 보고서 한 건으로 보충합니다. 스케줄은 중복 실행을 합치고 프로세스당 1개만 실행하며, PostgreSQL 트랜잭션 advisory lock으로 수동 요청 및 다른 프로세스와의 중복도 방지합니다.

Alembic `0018`에서 `redeployment_reports`를 추가합니다. `snapshot_date`는 KST 날짜의 유일 키이고, 같은 날 수동 갱신하면 해당 날짜의 저장본을 원자적으로 대체합니다. 과거 날짜 저장본은 유지합니다. Jira 수집이 끝나기 전에는 저장하지 않으며 페이지 누락·통신 오류·필수 날짜 누락 시 기존 저장본을 유지합니다. Assets 이름 조회 실패는 경고와 함께 저장할 수 있습니다. 갱신 실패 시 로그를 남기며 화면에서 오래된 보고서임을 표시합니다. 다음 정기 실행이나 `지금 갱신`으로 재시도합니다.

| API | 동작 |
|---|---|
| `GET /api/v1/redeployments/latest` | 최신 전체 스냅샷 또는 `null` |
| `POST /api/v1/redeployments` | 현재 시점 강제 갱신·저장, 성공 200, 동시 실행 409, Jira 실패 502 |

두 API 모두 기존 인증 규칙을 적용하며 `Cache-Control: no-store`를 반환합니다. 수동 생성은 `REDEPLOYMENT_REPORT_CREATE` 감사 이벤트를 기록합니다.

## 구조 및 검증

도메인은 보고서·티켓과 갱신 기준을 정의합니다. 애플리케이션은 포트 기반 수집/저장 순서를 조정하고, 인프라가 Jira 페이지 수집·Assets 조회·DB 트랜잭션·스케줄을 담당합니다. React는 주입된 gateway를 통해 조회하고 순수 집계 함수로 차트와 필터를 계산합니다. 기존 연간 재배포 위젯은 유지합니다.

검증: `python -m unittest tests.test_redeployment_report tests.test_container_lifecycle -v`, 프런트엔드에서 `node --test tests/redeployments.test.mjs` 및 `pnpm build`.
