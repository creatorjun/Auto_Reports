# SLA 현황 보고서

문서 기준: 2026-10-16.

## 화면과 저장

`집중 관리 항목` 하위의 `SLA 현황` 메뉴로 이동합니다. `/sla-violations`에 진입하면 서버에 마지막으로 저장된 SLA 현황 보고서를 자동으로 표시합니다. 저장된 보고서가 없으면 생성 안내를 표시합니다.

SLA 현황 화면은 기본적으로 현재 상태가 닫힘·반려됨·보류 중인 티켓을 제외해 표시합니다. 닫힘 별칭인 Closed·닫혀와 보류 중의 띄어쓰기 차이도 같은 기본값을 사용합니다. 사용자가 해당 상태나 전체 선택을 누르면 다시 표시하며, 저장 원본·위반 판정·히스토리 건수는 바꾸지 않습니다.

주간·월간·연간 토글과 날짜 선택기로 생성 조건을 정한 뒤 보고서를 생성합니다. 조회에 성공한 결과는 히스토리에 자동으로 저장되므로 별도의 저장 버튼은 없습니다. 조건을 변경해도 이미 표시 중인 보고서의 기간이나 데이터는 바뀌지 않으며, 새 보고서 생성에 성공하면 교체합니다. 생성 중에는 조건과 생성 버튼을 비활성화하고 실패하면 이전 보고서를 유지합니다.

`최초응답 위반`과 `해결 위반` 목록을 각각 표시합니다. 각 목록의 건수는 티켓 수이며, 같은 SLA를 여러 번 위반한 티켓도 목록에서는 한 번 표시합니다. 두 SLA를 모두 위반한 티켓은 양쪽 목록에 나타나므로 두 건수의 합과 전체 고유 티켓 수는 다를 수 있습니다.

대시보드와 같은 필터에서 요청 유형·현재 상태·상반기/하반기를 선택하고 전체 선택·해제를 할 수 있습니다. 조건을 함께 선택하면 모두 일치하는 티켓만 양쪽 위반 목록에 표시하며, 목록의 건수도 즉시 다시 계산합니다. 필터는 보고서 생성이나 저장 내용을 변경하지 않습니다. 같은 화면에서 동일 보고서를 다시 조회하면 선택을 유지하고 다른 보고서로 바뀌면 초기화합니다.

요청 유형과 현재 상태는 보고서 생성 시 저장된 값을 사용합니다. SLA 보고서의 모든 요청 유형을 선택지로 제공하며, 확인할 수 없는 값은 `확인 불가`로 표시합니다. 요청 유형을 저장하지 않은 과거 보고서는 다시 생성하면 해당 정보를 확인할 수 있습니다. 과거 이력을 열 때 현재 Jira 값으로 덮어쓰지 않습니다. 상반기는 티켓 생성일의 KST 1~6월, 하반기는 7~12월이며 보고서 집계 기간 안의 티켓에 적용합니다. 연도 경계를 지나는 주간도 각 티켓의 생성월로 판정합니다.

티켓은 접힌 상태로 번호·제목·유형·생성일·경과일을 표시합니다. 유형은 인시던트·개선 등 Jira 요청 유형이며, 저장된 값이 없으면 `확인 불가`로 표시합니다. 업무 유형별·상태별로 기존 팔레트를 바탕으로 고유 색상 배지를 지정하며 대시보드 최신 이슈·상세 표에서도 같은 색상을 사용합니다. 행의 링크는 Jira 원문을 새 탭으로 열고, 별도의 펼치기 버튼은 페이지 이동 없이 상세 정보를 표시합니다. 상세에는 최초응답·해결 SLA 목표와 초과 시간, 위반 항목·당시 상태·시각, 상태별 누적 체류시간, 고객사·담당 파트너사·보고자·담당자·TAC 담당자·집계 시점의 현재 상태가 있습니다. 고객사명과 인명 등 실제 상세 값은 기존 16px에서 공통 글꼴 단계의 다음 크기인 24px로 표시하고 항목 라벨은 14px를 유지합니다.

상태별 체류 기간에서는 `닫힘`과 같은 의미의 `닫혀`·`Closed` 항목을 표시하지 않습니다. 현재 상태나 SLA 위반 당시 상태가 닫힘인 경우에는 그 상태를 계속 표시합니다. 저장된 스냅샷과 경과일·위반 판정·집계는 변경하지 않으므로 기존 보고서에도 별도 생성 없이 적용됩니다.

상태별 시간 아래에는 한 줄 누적 막대로 체류 비율을 표시합니다. 닫힘을 제외한 표시 시간 합계를 100%로 계산하고 상태 배지와 같은 색상을 사용합니다. 막대 안에는 상태명과 비율을 함께 표시하며, 좁은 구간을 포함한 모든 구간에 마우스를 올리면 상태명·체류 시간·비율을 툴팁으로 확인할 수 있습니다. 각 시간 옆에도 비율을 표시하며 0.1% 미만은 `<0.1%`로 표기합니다. 합계가 0이거나 이력이 불완전한 경우에는 비율 막대를 표시하지 않습니다.

각 목록의 번호·제목·유형·생성일·경과일 컬럼명을 누르면 오름차순·내림차순을 번갈아 적용합니다. 번호는 숫자 부분을 고려하고 경과일은 숫자, 생성일은 실제 시각, 제목과 유형은 표시 문자열 기준으로 정렬합니다. 데스크톱에서 컬럼 사이 경계를 드래그하면 인접한 두 열의 너비를 조정합니다. 정렬과 너비는 최초응답·해결 목록별로 브라우저에 독립적으로 저장하며 필터 변경, 새로고침, 메뉴 재진입과 다른 보고서 조회 후에도 복원합니다. 저장된 보고서의 순서나 데이터는 바꾸지 않습니다. 설정은 같은 브라우저·사이트에서 유지되며 브라우저 저장소를 지우면 기본값으로 돌아갑니다. 저장소 사용이 차단되거나 저장값이 손상된 경우에도 기본값으로 화면을 사용할 수 있습니다.

기존 보고서 히스토리에서 SLA 현황 보고서 목록을 별도로 조회하고 `/sla-violations/history/:id`로 저장된 보고서를 다시 엽니다. 히스토리 조회는 Jira를 재수집하지 않으며 저장 당시의 값과 생성자·생성 시각을 유지합니다.

## 티켓별 SLA 목표와 초과 시간

티켓 상세에서는 최초응답 SLA와 해결시간 SLA를 나란히 비교합니다. 각 SLA의 설정 시간, Jira가 계측한 경과 시간, 초과 시간과 위반 여부를 표시하고, 위반한 주기는 당시 티켓 상태와 위반 시각을 함께 표시합니다. 완료·진행 중·일시정지 여부도 해당 주기의 Jira 값으로 구분합니다. 한 티켓에 재시작되거나 반복된 SLA 주기가 있으면 주기별 값을 각각 표시하며 서로 다른 목표나 초과 시간을 합산하지 않습니다. 어느 위반 목록에서 펼치더라도 두 SLA의 정보를 함께 확인할 수 있습니다.

| 표시 값 | 기준 |
|---|---|
| 최초응답/해결 SLA 설정 시간 | 각 티켓의 해당 SLA 주기에 적용된 Jira `goalDuration.millis` |
| SLA 사용 시간 | 같은 주기의 `elapsedTime.millis`; SLA 근무시간·휴일·일시정지 정책이 반영된 계측 경과 시간 |
| 초과 시간 | 동일 주기의 경과 시간 − 목표 시간, 또는 Jira 잔여 시간 `remainingTime.millis`의 반대 부호를 사용하고 0 미만은 0으로 표시 |
| 위반 항목 | 해당 주기의 `breached`에 따른 최초응답 SLA 또는 해결시간 SLA |
| 위반 당시 상태·시각 | 실제 위반 주기의 `breachTime`과 검증된 상태 변경 이력 |

고객사별 계약 등급이나 고정 목표 시간을 코드에서 추정하지 않습니다. Jira가 각 티켓·주기에 적용한 목표를 그대로 사용하므로 같은 고객사라도 주기별 설정 값이 다를 수 있습니다. 이 화면은 계약 수준을 편집하는 기능이 아닙니다.

초과 시간은 현재 시각에서 위반 시각을 빼서 구하지 않습니다. 완료된 SLA에는 완료 시점까지의 계측값을, 진행 중 또는 일시정지된 SLA에는 보고서 수집 시 받은 계측값을 저장합니다. 상태별 체류 기간은 별도의 실제 경과시간이므로 SLA 초과 시간을 특정 상태에 배분하거나 각 상태에 목표 시간이 있는 것으로 해석하지 않습니다. `위반 당시 상태`는 SLA 목표를 넘은 순간의 티켓 상태를 뜻합니다.

목표·경과·잔여 시간이 누락되거나 유효하지 않으면 확인 가능한 값만 표시합니다. 목표·경과·잔여 시간끼리 또는 위반 여부와 시간이 서로 모순되면 초과 시간을 `확인 불가`로 두고 데이터 경고를 남깁니다. 0은 확인된 0이며 미수집 값을 대신하지 않습니다. 위반하지 않은 진행 주기의 예정 `breachTime`은 실제 위반 시각으로 표시하지 않습니다.

이 기능 이전에 저장한 보고서는 SLA 주기 시간이 없으므로 해당 상세를 확인할 수 없습니다. 같은 기간으로 보고서를 새로 생성하면 수집 당시 Jira 값을 포함하는 새 이력이 만들어집니다. 기존 이력은 수정하거나 현재 Jira 값으로 보충하지 않습니다.

## 요약과 상세 탐색

`SlaViolationOverview`가 저장 티켓의 공통 필터 결과를 전체 위반 티켓·최초응답 위반·해결 위반·동시 위반 카드로 집계합니다. 동일 SLA 반복 위반은 티켓당 한 번이며 동시 위반은 두 SLA의 교집합입니다. 전체 건수를 두 SLA 건수의 합으로 계산하지 않습니다.

카드 선택은 현재 상태 분포와 생성 추이, 상세 목록의 SLA 범위를 함께 변경합니다. 현재 상태는 저장 당시 `current_status`이며 위반 당시 상태와 다릅니다. 연간 추이는 KST 생성월(1월~12월), 주·월간은 생성일(M/D)별이며 0건 구간도 표시합니다. 잘못되었거나 범위 밖인 생성일은 추이의 미분류 건수로 표시합니다.

상태·날짜 막대 선택과 검색어는 상세 티켓에 AND로 적용합니다. 검색 대상은 번호·제목·유형·상태·고객사·파트너·보고자·담당자·TAC 담당자입니다. 검색은 대소문자·유니코드 정규화를 적용합니다. 차트는 선택된 SLA 범위의 분포, 상단 카드는 공통 필터 결과를 유지하므로 상세 검색으로 전체 기준을 잃지 않습니다.

조건 칩을 개별 해제하거나 `상세 필터 초기화`로 카드·상태·날짜·검색을 해제합니다. 공통 필터는 그대로 유지합니다. 공통 필터를 바꾸면 차트의 상태·날짜 선택만 해제하며, 다른 보고서를 열면 페이지 필터를 초기화합니다. 최초응답/해결 범위는 해당 목록만 표시하고 전체/동시 범위는 두 목록을 표시합니다.

계산은 `frontend/src/domain/SlaViolationOverview.ts`에서 수행하며 추가 API·Jira 조회·DB 변경은 없습니다. 이 페이지에는 매일 08시 자동 생성이나 Rovo/A2A 분석 기능이 없습니다. 전체 사용 흐름은 [사용 가이드](../../frontend/docs/USER_GUIDE.md)에 있습니다.

## 집계 기준

- 시간대는 `Asia/Seoul`입니다. 주간은 선택 날짜가 속한 월요일~일요일, 월간은 해당 달의 첫날~말일, 연간은 해당 연도의 1월 1일~12월 31일입니다.
- 범위의 시작 자정은 포함하고 다음 기간 시작 자정은 제외합니다. 날짜 판정은 티켓의 `created`를 KST로 변환한 뒤 수행합니다. 미래 날짜는 허용하지 않습니다.
- Jira 프로젝트에서 요청 유형과 현재 상태를 제한하지 않고 해당 기간에 생성된 티켓을 조회합니다. 최초응답 또는 해결 SLA의 `completedCycles`·`ongoingCycle` 중 `breached=true`가 있는 티켓을 수집합니다.
- 기간은 생성일을 선택하는 조건입니다. SLA 위반 여부와 상세 상태는 보고서 생성 시점 기준이며, 과거 기간의 마지막 날 당시 상태를 재현하는 보고서가 아닙니다. 선택한 기간 이후에 발생한 위반도 해당 티켓이 위반한 이력에 포함합니다.
- 정확한 위반 시각은 Jira의 `breachTime`을 사용합니다. SLA 근무시간·휴일·일시정지 규칙을 임의로 계산하거나 시작 시각에 목표 시간을 더해 위반 시각을 추정하지 않습니다.
- 상태 변경 이력은 전체 페이지를 읽고 연속성을 확인합니다. 같은 상태 ID의 이름이 번역·변경된 경우 ID를 기준으로 표시명을 통일하며, ID가 없으면 이름의 연속성을 확인합니다. 상태가 바뀐 시각에 위반했다면 새 상태를 사용합니다. 이력이 불완전하거나 정확한 위반 시각이 없으면 해당 상세를 `확인 불가`로 표시하고 티켓은 위반 목록에 유지합니다.
- 상태별 체류시간은 티켓 생성부터 보고서 생성까지 실제 경과시간을 합산합니다. 같은 상태로 돌아오면 합산하며, 근무시간·휴일·SLA 일시정지 시간을 차감한 SLA 시간과는 다릅니다.
- 경과일은 KST 기준 보고서 생성 날짜와 티켓 생성 날짜의 차이입니다. 이후 히스토리를 열어도 저장 당시 값은 유지합니다.
- 파트너 필드가 실제로 비어 있으면 `본사`, 파트너 지정 여부나 이름을 확인할 수 없으면 `확인 불가`입니다. 다른 미확인 인적·고객사 정보도 `확인 불가`로 표시합니다.

## Jira 필드와 오류 처리

| 항목 | 필드 |
|------|------|
| 최초응답 SLA | `SLA_INITIAL_RESPONSE_FIELD_ID`, 기본 `customfield_12152` |
| 해결 SLA | `SLA_RESOLUTION_FIELD_ID`, 기본 `customfield_12151` |
| 고객사 | `customfield_11022`, 비어 있으면 Assets `customfield_10854` |
| 담당 파트너사 | Assets `customfield_10859` |
| TAC 담당자 | `JIRA_RECENT_TAC_ASSIGNEE_FIELD_ID`, 기본 `customfield_12522` |
| 보고자·담당자 | `reporter`, `assignee` |
| 요청 유형 | `issuetype.name` |

티켓 검색과 상태 변경 이력은 모든 페이지를 조회하며, Jira HTTP 동시 요청은 최대 5개입니다. 통신·인증 실패나 잘린 검색 응답은 정상적인 빈 보고서로 저장하지 않습니다. 티켓별 데이터 누락과 불완전한 상태 이력은 보고서와 해당 티켓의 `warnings`로 표시합니다.

## API

모든 경로는 `/api/v1` 아래의 기존 인증 보호 라우트입니다.

| Method | Path | 요청·응답 |
|--------|------|----------|
| POST | `/sla-violations` | `{ "period": "week", "date": "2026-10-07" }`; 생성·저장 후 201과 전체 보고서 |
| GET | `/sla-violations/latest` | 마지막 저장 보고서 또는 `null` |
| GET | `/sla-violations/history?limit=20&offset=0` | 최신 생성순 요약 목록, limit 1~100·offset 0 이상 |
| GET | `/sla-violations/{id}` | 저장 보고서, 없으면 404 |

잘못된 기간·날짜는 422, 이미 생성 중이면 409, Jira 수집 실패는 502입니다. 읽기 응답은 `Cache-Control: no-store`이며, 생성에 성공하면 `SLA_VIOLATION_REPORT_CREATE` 감사 이벤트를 기록합니다. 프런트엔드 생성 요청은 최대 10분을 기다립니다.

티켓 응답의 `issue_type`은 문자열 또는 null입니다. 새 보고서는 요청 유형을 JSON payload에 함께 저장하며, 이전 payload에 필드가 없으면 null로 반환합니다.

`sla_cycles`는 티켓별 최초응답·해결 SLA의 완료 주기와 진행 주기를 보존하는 배열입니다. 위반하지 않은 주기도 포함하며, 목록의 포함 여부와 건수는 기존 `breaches`의 위반 항목만 사용합니다. 각 원소는 `metric`, `breached`, `ongoing`, `paused`, `goal_ms`, `elapsed_ms`, `exceeded_ms`, `started_at`, `stopped_at`, `breached_at`, `status`를 제공합니다. 시간량은 밀리초 단위 정수 또는 null, 시각은 시간대가 포함된 ISO 8601 문자열 또는 null입니다. `status`는 위반 당시 상태이고 미위반 주기에는 null입니다. 이전 payload에 `sla_cycles`가 없으면 null로 반환하고, 새 수집 결과의 빈 배열과 구분합니다. 필드는 기존 JSONB에 저장하므로 DB 스키마 마이그레이션은 필요하지 않습니다.

## 저장 구조와 검증

Alembic `0017_add_sla_violation_reports`가 `sla_violation_reports` 테이블을 만듭니다. 기간·선택 날짜·생성 시각·생성자·고유 티켓 수·각 SLA 티켓 수와 상세 JSONB를 함께 저장합니다. 최신 조회는 `generated_at DESC, id DESC` 순서입니다. 일반·연간 보고서 테이블과 독립적이며 `REPORT_RETENTION_WEEKS`의 자동 정리 대상이 아닙니다. SLA 이력 삭제 API·화면은 현재 없습니다.

Domain은 보고서와 이력 모델, Application은 기간·상태 이력 계산과 생성·저장 유스케이스 및 포트를 소유합니다. Infrastructure는 Jira·Assets HTTP와 DB 직렬화를 맡고, Presentation은 인증·API·React UI를 담당합니다. HTTP 클라이언트와 생성 동시성 제어는 Container에서 조립하고 앱 종료 시 정리합니다.

```bash
cd backend
python -m unittest discover -s tests -p "test_sla_violation*.py" -v
cd ../frontend
pnpm test:sla-violations
pnpm build
```
