검토일: 2026-10-21. 기준 소스: `1e106fef3ef924abaad853ec46c58a6fa494610b`.

## 검토 범위

`backend/src` Python 234개, 운영·진단 스크립트 13개, Alembic 진입점과 migration 25개를 모두 읽고 호출 흐름, SQL·HTTP 요청 수, 자료 변환, 비동기 대기, 캐시와 작업 수명을 확인했습니다. Docker 실행 설정과 기존 회귀 검사도 대조했습니다.

## 전후 측정

벽시계 측정은 실행 환경과 데이터에 따라 달라집니다. SQL·HTTP 횟수는 회귀 테스트에서 검증하며, 내부 처리시간을 화면 전체 응답시간으로 해석하지 않습니다.

| 비교 조건 | 기존 | 변경 |
|---|---:|---:|
| 개인정보 계정 1,001개 등록의 UPSERT 수 | 1,001 | 3 |
| 재시도 대기 번역 후보 1,001개의 후보 SELECT 수 | 2,002 | 8 |
| 이미 번역된 후보 1,001개의 후보 SELECT 수 | 1,001 | 4 |
| 즉시 예약 가능한 후보의 처음 10개 처리 | 후보별 조회 | 10개만 순회, SELECT 2회 |
| SSE 상태 확인 후 변경 대기 1주기의 DB 읽기 | 3 | 2 |
| 동일 자산을 동시에 요청하는 5개 티켓의 HTTP 호출 | 5 | 1 |

Windows 합성 시험에서 상태이력 50개에 불균일한 응답 지연을 주었을 때 중앙값은 627.29ms에서 282.21ms로 감소했습니다. SLA 상세의 별도 50개 티켓 시험은 472.4ms에서 245.3ms였습니다. 양쪽 모두 최대 동시성 5와 결과 순서를 유지했습니다.

600개 뉴스의 반복 내부 처리 중앙값은 미번역 상태에서 37.21ms에서 0.36ms, 번역 완료 상태에서 43.76ms에서 4.21ms였습니다. 원본 커밋과 반환 객체 전체를 비교했습니다. 합성 시험은 HTTP·인증·외부 네트워크 시간을 포함하지 않습니다.

SQLite 최종 임시 DB 시험은 1,001개 지연 후보에서 7.034ms에서 4.669ms, 번역 완료 후보에서 4.159ms에서 3.362ms였습니다. 반환값과 예약·번역·예산·제어 테이블의 상태를 대조했습니다. 처음부터 400개를 읽는 초안은 즉시 예약 경로에서 느려져 폐기하고, 필요한 수부터 조회하는 방식으로 조정했습니다.

## 유지한 기능과 검증

보고서 집계 기간·JQL·정렬·정확한 건수, SLA 업무시간·잔여율, 개인정보 삭제·프로필 갱신, Jira 로그인·권한, 알림 전송, 번역 모델·무료 티어 정책·수집 주기와 공개 API는 변경하지 않았습니다. DB schema와 migration도 변경하지 않았습니다.

기존 Jira 요청 병합·HTTP 연결 재사용, 보고서/사이트 요약 컬럼 조회, DB snapshot 우선 표시, 파일 I/O의 비동기 위임, 감사로그의 제한된 메모리 사용을 확인하고 유지했습니다. 인증 결과·개인정보를 새 캐시로 우회하거나 파일 용량·로그 합계를 근사값으로 바꾸지 않았습니다.

회귀 검사는 결과 동등성 외에도 번역 완료 즉시 표시, 원문 변경·실패 시 캐시 처리, SQL 상한, 중복 계정, 개인정보 상태, 중간 일괄 처리 실패 시 롤백, 동시에 실행되는 번역 예약, 느린 티켓과 완료 순서, 구독 중 알림, 저장소 오류와 취소 시 정리를 포함합니다. 운영과 분리된 Linux·PostgreSQL DB에서 전체 검사를 실행하고, 운영 배포에서는 설정·DB·프론트엔드를 보존하며 검사한 백엔드 이미지 ID와 실행 이미지 ID가 일치하는지 확인합니다.

최종 Linux Python 3.11·PostgreSQL 16 검사는 1,068개 모두 통과했습니다. Windows Python 3.14 검사도 1,068개 중 환경 전용 53개를 건너뛰고 통과했습니다. PostgreSQL 검사는 격리된 Linux 환경에서 전부 실행했으며, 소스·테스트·운영 스크립트의 compileall과 diff 공백 검사도 통과했습니다.
