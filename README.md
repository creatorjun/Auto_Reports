# Auto Reports Workspace

Jira 데이터를 수집해 주간 보고서, 파트너 현황, 고객사 사이트 정보와 파일 저장소를 제공하는 사내 통합 워크스페이스입니다. FastAPI 백엔드와 React 대시보드를 하나의 Docker Compose 스택으로 운영합니다.

## 프로젝트 구조

```text
Auto_Reports/
├── backend/
│   ├── src/
│   │   ├── domain/          핵심 엔티티와 값 객체
│   │   ├── application/     유스케이스와 포트
│   │   ├── infrastructure/  DB, Jira, 메일, 파일, 스케줄러 어댑터
│   │   ├── presentation/    FastAPI 라우터, 스키마, 매퍼
│   │   ├── bootstrap/       의존성 조립
│   │   └── main.py          프로세스 Composition Root
│   ├── tests/               아키텍처와 핵심 동시성 회귀 테스트
│   └── docs/
├── frontend/
│   ├── src/
│   │   ├── domain/          프레임워크 독립 모델
│   │   ├── application/     게이트웨이 계약과 애플리케이션 오류
│   │   ├── infrastructure/  axios API 어댑터
│   │   ├── presentation/    React UI, 훅, 상태, 컨텍스트
│   │   ├── app/             라우터와 앱 셸
│   │   └── main.tsx         브라우저 Composition Root
│   ├── tests/               의존 방향 아키텍처 테스트
│   └── docs/
├── docker-compose.yml
└── Makefile
```

의존성은 안쪽을 향합니다. Domain은 어떤 프레임워크도 알지 못하고, Application은 Domain과 자체 포트만 사용합니다. Infrastructure와 Presentation은 Application 포트에 의존하며, 실제 구현 연결은 각 실행 진입점에서만 수행합니다.

첫 번째 대시보드는 보고서 생성 시 Jira 프로젝트에 현재 등록된 모든 요청 유형을 조회해 화면 최상단 토글에 표시하고, 모든 위젯과 상세 모달에서 실시간 포함·제외할 수 있습니다. 같은 선택 영역의 상반기·하반기 버튼은 보고서 연도의 월별 집계와 상세 일시를 기준으로 전체 대시보드를 6개월 단위로 필터링하며, 선택하지 않으면 연간 전체를 표시합니다. `ISSUE_TYPES`는 Jira 유형 목록 조회 실패 시에만 사용하는 안전한 기본값입니다. 기존 보고서는 이 집계 계약으로 한 번 생성하거나 갱신해야 전체 유형 및 반기 필터가 활성화됩니다.

## 대시보드 보고서 생성

대시보드의 PDF·Excel 내보내기 영역 바로 아래에서 **주간·월간·연간 → 기준일 → 보고서 생성** 순서로 실행합니다. 주간은 월요일부터 일요일, 월간은 해당 달 전체, 연간은 해당 연도 전체를 KST 기준으로 사용합니다. 기간이나 날짜만 변경하면 표시 중인 보고서는 유지되며, 생성에 성공하면 저장된 새 보고서를 표시합니다. 이력이 없는 상태에서도 같은 폼으로 첫 보고서를 생성할 수 있습니다.

보고서 히스토리는 대시보드와 SLA 현황 페이지 상단의 **보고서 히스토리** 버튼으로 엽니다. 데스크톱·모바일 대메뉴에는 표시하지 않으며 기존 히스토리 페이지와 저장 보고서 조회 기능은 유지합니다.

기존 지표·차트·상세 표·필터·내보내기를 유지하며, 대시보드의 연간 선택도 같은 대시보드 구성으로 표시합니다. 기간별 생성·완료 지표에는 선택한 기간을 적용하고, 기존 연도별 지표와 현재 미해결 지표의 집계 기준은 유지합니다. 좌측 메뉴와 모바일의 별도 생성 버튼, 최근 7일 보고서를 생성하던 헤더 새로고침 버튼은 제거했습니다. Ctrl+R은 브라우저 새로고침으로 동작합니다.

별도 **연간 보고서** 메뉴의 전용 지표도 유지합니다. 해당 연도 화면의 생성 버튼으로 과거 연도는 1월 1일~12월 31일, 현재 연도는 1월 1일~오늘을 집계합니다. 이 보고서는 대시보드의 최신 일반 보고서를 대체하지 않습니다.

## 집중 관리 항목

대시보드 다음의 **집중 관리 항목** 아래에 **재배포 현황 → SLA 현황 → 장기 이슈 → 전체 이슈**를 배치합니다. 데스크톱의 집중 관리 항목·연간 보고서는 마우스를 올리면 자동으로 펼쳐지며 클릭 또는 키보드로도 열고 닫을 수 있습니다. 모바일은 집중 관리 항목 버튼을 눌러 같은 하위 메뉴를 엽니다. 기존 페이지 주소와 저장된 보고서 링크는 유지합니다.

## SLA 현황 보고서

**집중 관리 항목 → SLA 현황** 메뉴에서 주간·월간·연간과 기준 날짜를 선택해 생성일 기준 위반 티켓을 집계합니다. 최초응답 위반과 해결 위반 목록에 번호·제목·유형·생성일·경과일을 표시하고, 접힌 티켓을 펼쳐 위반 당시 상태·상태별 체류시간·고객사·파트너·담당자 정보를 확인합니다. 행을 누르면 Jira 원문을 새 탭으로 엽니다.

생성에 성공하면 히스토리에 자동 저장하며, 메뉴에 다시 들어오면 마지막 생성 보고서를 표시합니다. 저장된 값은 생성 시점 기준입니다. 집계 정의, 누락 데이터 처리, Jira 필드와 API는 [SLA 현황 보고서 문서](backend/docs/08_sla_violation_report.md)를 참고하세요.

대시보드와 같은 요청 유형·현재 상태·상반기/하반기 필터와 전체 선택·해제를 제공합니다. SLA 현황에 진입하거나 다른 보고서를 열면 닫힘·반려됨·보류 중을 기본 해제하며, 개별 상태 또는 전체 선택으로 다시 포함할 수 있습니다. 두 위반 목록과 건수가 함께 갱신되며 저장된 보고서는 유지됩니다. 요청 유형을 수집하지 않은 과거 보고서는 `확인 불가`로 표시하고, 새로 생성하면 유형별 필터를 사용할 수 있습니다.

## 재배포 현황

**집중 관리 항목 → 재배포 현황** 메뉴는 매일 08:00 KST에 자동 생성됩니다. 2026-01-01 이후 해결된 재배포 완료 티켓과 현재 진행 중인 티켓을 구분하며 원인 분포, 월별 완료, 상세 사유, 기록된 재패치 횟수를 제공합니다. 생성일이 이전 연도인 완료 티켓도 포함합니다. 최신 저장본을 자동으로 표시하고 ‘지금 갱신’으로 즉시 재수집할 수 있습니다. 자세한 집계·저장·스케줄 계약은 [재배포 보고서 문서](backend/docs/09_redeployment_report.md)를 참고하세요.

## 전체 이슈

**집중 관리 항목 → 전체 이슈** 메뉴(`/issues`)는 TACEA 프로젝트에서 연결된 Jira 계정이 조회할 수 있는 모든 항목을 표시합니다. 최초 전체 수집은 백그라운드에서 페이지 제한 없이 진행하며 완료 상태도 포함합니다. 요청 유형·현재 상태·상반기/하반기 필터는 대시보드와 같은 UI를 사용하고, 생성 연도를 선택하지 않으면 전체 연도에 적용됩니다. 목록은 최근 이슈 현황의 표를 재사용하며 경과일 검색, 정렬, 열 너비 조절과 페이지 이동을 제공합니다.

상단에서 PDF 또는 Excel (.xlsx)을 선택해 현재 필터와 7개 컬럼의 검색어에 맞는 전체 이슈를 다운로드할 수 있습니다. 표의 페이지 번호와 관계없이 모든 일치 항목을 포함하며 적용 조건을 파일에 표시합니다. 다운로드를 시작할 때 목록과 검색 조건을 복사하므로 생성 중 자동 동기화나 화면 필터 변경은 파일 내용에 영향을 주지 않습니다.

화면이 열려 있는 동안 30초 간격으로 변경분을 조회하고 이슈 키를 기준으로 캐시에 추가하거나 갱신합니다. Jira 검색 인덱스 반영 지연을 고려해 최근 2분 이상을 중복 조회합니다. 동기화 중에는 2초 간격으로 캐시 상태를 확인하며 기존 목록과 페이지를 유지합니다. 실패하면 마지막 성공한 캐시와 동기화 시점을 유지하고 재시도합니다. 매시간 전체 재조회로 삭제 및 프로젝트 이동 항목을 정리합니다. 캐시는 백엔드 프로세스 메모리에 있으며 재시작 시 전체 수집을 다시 수행합니다. 화면 갱신 시점은 Jira 검색 인덱스 및 API 응답 속도에 영향을 받습니다.

인증이 적용된 `GET /api/v1/issue-management/issues`는 `issues`, `initialized`, `refreshing`, `synced_at`, `error`를 반환합니다. 최초 수집 중인 빈 목록과 실제 조회 결과가 없는 상태는 `initialized`로 구분합니다.

## 관리자 감사로그

`ADMIN`은 일반 사용자이고 `SUPERADMIN`은 관리자입니다. 관리자 로그인 시 표시되는 **감사로그** 메뉴(`/audit-logs`)에서 기존 작업 기록과 로그인·로그아웃 기록을 기간·사용자·IP·이벤트로 조회합니다. 일반 사용자는 메뉴와 API 모두 접근할 수 없습니다. Docker Compose의 `audit_logs` 볼륨에 로그를 보관하며, 최초 배포 전 기존 컨테이너 로그의 이전 방법은 [감사로그 문서](backend/docs/07_audit_logs.md)를 참고하세요.

## 실행

루트에 `.env`를 준비한 뒤 전체 스택을 실행합니다.

```bash
docker compose up -d --build
docker compose logs -f tac_backend
```

```bash
git pull && docker compose down && docker compose build --no-cache && docker compose up -d && docker logs -f tac_backend
```

기본 접속 주소는 `http://localhost`이고 백엔드 상태 확인은 `GET /api/health`입니다. 환경 변수는 [backend/docs/04_environment_and_config.md](backend/docs/04_environment_and_config.md)를 참고하세요.

백엔드 시작 시 `alembic upgrade head`를 자동 실행합니다. C-Level 기능 제거에 따른 `0016` 마이그레이션은 해당 기능의 저장된 보고서와 코멘트 테이블을 삭제합니다. 기존 데이터가 필요하면 배포 전에 DB를 백업해야 하며, downgrade는 빈 테이블 구조만 복원합니다. [마이그레이션 안내](backend/docs/03_data_model.md#migration)를 참고하세요.
