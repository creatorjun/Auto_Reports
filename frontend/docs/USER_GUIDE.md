# 화면 사용 가이드

문서 기준: 2026-10-16.

화면 표시명은 SecuLayer이며, API 및 내부 파일 이름은 호환성을 위해 기존 이름을 유지합니다.

## 메뉴와 공통 조작

로그인 화면(`/login`)의 **Jira 계정으로 로그인**을 누르면 Atlassian에서 인증·승인한 뒤 돌아옵니다. 회사 Jira와 TACEA 프로젝트 조회 권한이 있는 활성 사용자에게 일반 사용자 권한을 부여합니다. Jira 로그인 연동 설정이 끝나야 버튼을 사용할 수 있습니다. 기존 admin·superadmin 계정은 `/admin` 주소에 직접 접속해 로그인합니다. 관리자 로그인은 일반 로그인 화면과 메뉴에 노출하지 않습니다. Jira 계정에는 감사로그 관리자 권한을 부여하지 않습니다.

정상 로그인 후에는 새로고침하거나 브라우저를 다시 열어도 유효한 로그인 cookie로 자동 로그인합니다. Jira 로그인은 기본 7일 뒤 다시 인증하며 cookie를 삭제하면 재로그인이 필요합니다. 로그아웃하면 현재 브라우저의 로그인 상태를 지웁니다. 구성·운영 절차는 [Jira 로그인](../../backend/docs/11_jira_login.md)을 참고하세요.

로그인 표시 이름은 서버에서 복원해 브라우저 메모리에서만 사용합니다. 이전 버전이 저장한 로그인 표시 정보는 서비스 시작 시 제거하고 테마·표 설정은 유지합니다.

Jira 사용자의 표시 이름은 서버 프로필에서 관리하며 Jira JWT에는 포함하지 않습니다. 개인정보 보고에서 계정 삭제·변경이 확인되면 기존 세션이 무효화됩니다. 변경된 계정은 Jira에서 다시 로그인해 최신 프로필을 확인합니다.

최고 관리자는 `/admin/jira-privacy`에 직접 접속해 앱 소유자의 개인정보 정기 보고 연결과 처리 상태를 확인합니다. 일반 사용자와 일반 관리자에게는 연결 상태나 제어가 표시되지 않습니다. 별도 소유자 승인에서만 offline_access를 요청하며, 해당 refresh token을 서버에 암호화해 보관합니다. 이 화면에 접근하거나 코드를 배포한 것만으로 Atlassian 앱 공유가 활성화되는 것은 아닙니다.

로그인 화면 하단에서 개인정보처리방침(`/privacy`)과 이용약관(`/terms`)을 확인할 수 있습니다. 두 페이지는 로그인 없이 열리며, 운영 주체는 SecuLayer, 시행일은 2026-10-16, 문의 주소는 `jh.han@seculayer.com`입니다. 인증·자동 로그인, Jira 업무자료와 저장 보고서, 감사로그, 선택 기능의 연동 및 정정·삭제 요청 방법을 안내합니다.

메뉴 순서는 대시보드 → 전체 이슈 → 집중 관리 항목 → 연간 보고서 → 파트너 관리 → 사이트 관리 → 장기 이슈 → 파일 보관함입니다. 집중 관리 항목은 SLA 현황 → 재배포 현황 순서입니다. 연간 보고서에는 2024·2025·2026이 있습니다.

데스크톱에서는 하위 메뉴가 있는 버튼에 마우스를 올려 펼칩니다. 하위 메뉴로 이동하는 동안 유지되고 영역을 벗어나면 닫힙니다. 빈 사이드바에 마우스를 올리는 것만으로 펼쳐지지 않습니다. 모바일은 버튼 클릭, 바깥 영역 클릭 및 Escape를 사용합니다. 관리자 감사로그는 권한이 있는 계정에만 나타납니다.

헤더 로고는 브라우저 전체 폭의 가운데에 고정됩니다. 라이트·다크 모드는 다른 PNG 원본을 사용하며 테마 선택은 같은 브라우저에 저장됩니다. 고정 사용법·자동 저장 안내는 화면에서 생략하지만, 오류와 실제 데이터 누락 경고는 계속 표시합니다.

화면의 세 단계 글자 크기는 기존보다 각각 2pt 커졌으며 굵기는 그대로입니다. 차트와 Markdown 미리보기 본문에도 적용하고, PDF의 별도 인쇄 조판이나 업로드한 파일의 원본 서식은 바꾸지 않습니다. 내보내는 차트의 글자 크기는 화면과 같은 중앙 설정을 따릅니다.

## 대시보드

1. 상단 내보내기 영역 다음의 생성 폼에서 주간·월간·연간을 선택합니다.
2. 기준일을 고른 뒤 **보고서 생성**을 누릅니다. 미래 기준일은 선택할 수 없습니다.
3. 완료되면 새 보고서를 표시하고 히스토리에 저장합니다. 조건만 변경하면 기존 보고서는 그대로 보입니다.

대시보드 주간은 KST 기준 선택 날짜가 속한 주의 월요일~선택 날짜, 월간은 해당 달 전체, 연간은 해당 연도 전체입니다. 기준일이 2026-10-09이면 주간은 10월 5일~9일, 월간은 10월 1일~31일, 연간은 1월 1일~12월 31일입니다. 종료일 당일 전체를 포함하며 월·연간의 미래 구간에는 실제 존재하는 데이터만 집계합니다. SLA 현황도 같은 기간 기준을 사용합니다. 기존 저장 보고서의 기간은 변경하지 않으므로 새 기준은 보고서를 생성할 때 적용됩니다. 위젯마다 연간 누적·선택 기간·현재 미완료 집합처럼 집계 기준이 다릅니다. 생성 범위를 바꿔도 기존 지표의 의미를 모두 같은 기간으로 바꾸지는 않습니다. SLA 준수율 차트의 월은 `1월`, `2월`로 표시합니다.

요청 유형·현재 상태·반기 필터로 보고서를 좁힙니다. 라이선스는 대시보드·연간 보고서에서 제외합니다. 승인된 서비스 요청·케이스는 유형 버튼에서는 숨겨도 집계에는 포함하는 기존 정책을 유지합니다. 옛 보고서에 상태별 집계가 없으면 해당 필터가 비활성화될 수 있으며 재생성으로 최신 데이터를 수집합니다.

최근 이슈 표에는 보고서 시작일~종료일에 생성된 열린 이슈만 표시합니다. 양쪽 경계 날짜를 모두 포함하며 생성일은 KST 기준, 열림 여부는 보고서가 마지막으로 수집한 Jira 상태 기준입니다. 일반·저장·연간 보고서와 PDF·Excel에 동일하게 적용하고, 업무 유형별 열린 요청 카드와 장기 이슈의 전체 미완료 집합은 유지합니다. 최근 이슈 표에서 컬럼 검색, 경과일 조건, 정렬과 열 너비를 조절할 수 있습니다. 정렬·열 너비는 일반·저장·연간 대시보드가 같은 브라우저 설정을 공유합니다. 필터·검색·페이지는 이 저장 대상에 포함되지 않습니다.

대시보드와 전체 이슈 표의 **초기화**는 경과일 조건과 모든 컬럼 검색어를 함께 지우고 첫 페이지로 돌아갑니다. 컬럼 검색어만 입력한 경우에도 초기화할 수 있으며, 상단 업무 유형·현재 상태·반기 필터와 정렬·열 너비는 유지됩니다.

**이슈 리뷰 중·자료 요청 중·결과 대기 중** 카드와 상세 목록은 마지막 Jira 수집 시점에 미완료이면서 현재 단계가 해당 상태인 전체 이슈를 표시합니다. 생성일·보고서 기간·반기로 제한하지 않으며, 과거에 해당 단계를 거쳤는지나 SLA 초과 여부로 선택하지 않습니다. 업무 유형·현재 상태 필터는 카드와 상세 목록에 동일하게 적용됩니다. 기간 제한을 적용해 저장했던 보고서나 최신 Jira 상태를 다시 확인하려는 보고서는 생성 또는 갱신하여 전체 이슈를 수집합니다.

대시보드 카드·차트를 눌러 여는 모든 이슈 표 모달은 컬럼명을 누르면 오름차순·내림차순으로 정렬됩니다. 모바일에서는 정렬 컬럼과 방향을 선택합니다. 이슈 번호는 숫자 부분을 고려하고, 경과일·처리시간은 숫자, 생성·해결일시는 시각 기준으로 정렬합니다. 연간 차트 상세의 검색 결과도 전체 일치 목록을 먼저 정렬한 뒤 페이지를 나누며, 정렬 조건을 바꾸면 첫 페이지로 이동합니다.

PDF 또는 Excel을 선택해 내보내면 생성 시작 시의 필터·검색 결과 전체가 파일에 포함됩니다. 현재 표 페이지에만 제한하지 않습니다. 이후 화면 조건이나 데이터가 바뀌어도 생성 중인 파일의 대상은 유지됩니다. 연간 재배포 품질 지표는 별도의 연도 전체 기준을 유지합니다.

## 연간 보고서

연간 메뉴에서 연도를 선택합니다. 과거 연도는 1월 1일~12월 31일, 현재 연도는 1월 1일~오늘까지 전용 보고서를 생성합니다. 대시보드의 연간 선택 보고서와 저장 범위가 다르므로 최신 일반 대시보드를 바꾸지 않습니다.

월별·연도별 비교와 재배포 품질 지표를 볼 수 있습니다. 일부 차트 상세는 클릭 시 현재 Jira를 조회하므로 저장된 차트 수치와 달라질 수 있습니다. SLA 현황의 저장 이력 조회와는 다른 동작입니다.

현재 프런트엔드 연도 목록과 5분 자동 조회 대상은 2024·2025·2026 및 2026으로 설정되어 있습니다. 연도가 바뀌면 [연도 설정](../src/presentation/config/annualReports.ts)을 갱신해야 합니다. 백엔드의 연간 자동 갱신 대상은 서버가 판단한 현재 연도입니다.

## SLA 현황

메뉴에 들어가면 마지막 저장 보고서를 표시합니다. 주·월·연과 기준일을 선택하고 생성하면 성공한 보고서를 새 이력으로 저장합니다. SLA 보고서의 매일 자동 생성은 현재 제공하지 않습니다.

주간은 해당 주 월요일부터 기준일까지, 월간은 해당 달 전체, 연간은 해당 연도 전체이며 KST 기준 종료일 당일을 포함합니다. 기준일이 2026-10-09이면 주간은 10월 5일~9일입니다. 이전에 월요일~일요일로 저장한 보고서는 그대로 표시합니다. 선택한 날짜가 같아도 저장된 기간과 새 생성 기간이 다르면 안내가 표시되며, **보고서 생성**을 누르면 새 기준의 보고서를 별도 이력으로 저장합니다.

기간은 **티켓 생성일**로 고릅니다. 예를 들어 1월 생성 티켓이 3월에 위반했다면 3월 이후 생성한 1월 보고서에 포함될 수 있습니다. 위반 여부·현재 상태·경과일·체류시간은 보고서 생성 당시 값이며 이력을 열 때 현재 Jira 값으로 바꾸지 않습니다.

상단 공통 필터는 요청 유형·현재 상태·반기를 함께 적용합니다. 처음에는 닫힘·반려됨·보류 중을 해제합니다. 제외 상태를 직접 선택하거나 전체 선택으로 포함할 수 있습니다. 화면에서 숨긴 티켓은 저장 원본이나 히스토리 건수에서 삭제되지 않습니다.

| 영역 | 사용 방법 |
|---|---|
| 전체 위반 티켓·최초응답·해결·동시 위반 카드 | 선택한 SLA 범위의 차트와 상세 목록 표시. 같은 카드를 다시 선택하면 전체로 복귀 |
| 현재 상태 분포 | 상태를 눌러 상세 목록 필터링. 저장 당시 현재 상태 기준 |
| 생성 추이 | 연간은 생성월, 주·월간은 KST 생성일. 막대를 눌러 상세 목록 필터링 |
| 검색 | 번호·제목·고객사·파트너·보고자·담당자·TAC 담당자·유형·상태 검색 |
| 조건 칩 | SLA 범위·상태·날짜 선택 해제. 검색어는 검색창에서 지움 |
| 상세 필터 초기화 | 카드·상태·날짜·검색을 해제하고 공통 필터는 유지 |

상태·날짜·검색은 교집합으로 상세 목록에 적용합니다. 카드의 수치는 공통 필터 결과를 유지하며, 차트는 선택한 SLA 범위의 분포를 유지합니다. 공통 필터를 바꾸면 차트의 상태·날짜 선택을 해제합니다. 같은 티켓이 같은 SLA를 여러 번 위반해도 카드에서는 한 번 계산하고, 두 SLA를 모두 위반하면 동시 위반에도 포함합니다.

**SLA 위반 티켓** 목록은 **번호·제목·유형·위반 항목·생성일·경과일** 순서이며 처음에는 접혀 있습니다. `위반 항목`에는 **최초응답 위반** 또는 **해결시간 위반** 배지를 표시하며, 두 SLA를 모두 위반한 티켓은 한 행에 두 배지를 함께 표시합니다. 같은 SLA를 반복 위반해도 티켓 행과 배지는 중복하지 않습니다. 상단 최초응답·해결·동시 위반 카드를 선택하면 이 목록에서 해당 티켓만 볼 수 있습니다.

컬럼명을 클릭해 정렬 방향을 바꾸고 데스크톱에서는 경계를 드래그해 너비를 조절합니다. 통합 목록에서 저장한 정렬·너비는 카드와 필터를 바꾸거나 새로고침·메뉴 재진입 후에도 복원합니다. 이전 최초응답·해결 분리 목록의 설정은 가져오지 않아 통합 목록의 기본 설정으로 시작합니다.

행을 누르면 Jira를 새 탭으로 열고, 행 오른쪽의 아래 방향 화살표 버튼은 페이지 이동 없이 상세를 펼칩니다. 재배포 현황과 같은 아이콘 버튼이며 다시 누르면 접힙니다. 고객사·파트너, 보고자·담당자·TAC 담당자와 현재 상태의 실제 값은 항목 이름보다 크게 표시합니다. 파트너 미지정은 **본사**, 조회할 수 없는 값은 **확인 불가**입니다.

펼친 상세에서는 **최초응답 SLA와 해결시간 SLA를 함께 비교**합니다. 상단 카드에서 선택한 위반 범위와 관계없이 두 항목의 설정 시간, SLA 사용 시간과 초과 시간을 확인할 수 있습니다. 고객사 이름으로 목표를 추정하지 않고 Jira가 해당 티켓에 적용한 목표를 사용합니다.

| 상세 항목 | 읽는 방법 |
|---|---|
| SLA 설정 시간 | 해당 주기에 적용된 목표. 고객사·계약과 Jira SLA 설정에 따라 달라질 수 있음 |
| SLA 사용 시간 | 근무시간·휴일·일시정지 정책을 반영해 Jira가 계측한 경과 시간 |
| 초과 시간 | 해당 주기가 목표보다 초과한 SLA 시간. 예: 목표 4시간, 경과 7시간이면 3시간 초과 |
| 위반 항목·당시 상태 | 최초응답 또는 해결시간 중 어떤 SLA를 위반했는지와 위반 순간 티켓이 머물던 상태 |
| 주기 상태 | 종료·진행 중·일시정지 여부. 반복되거나 재시작된 주기는 각각 표시 |

위반 당시 상태가 `연구소 검토 중`이라고 해서 그 상태에 별도의 SLA 목표가 있거나 초과 시간이 전부 그 상태에서 발생했다는 뜻은 아닙니다. 위반은 해당 SLA 주기 전체의 목표로 판정하며, 반복 주기의 목표·경과·초과 시간은 합치지 않습니다. 진행 중인 SLA도 저장된 보고서 수집 시점의 값이며 화면을 열어 둔다고 시간이 증가하지 않습니다.

이전에 만든 보고서는 SLA 시간 정보가 없을 수 있습니다. 같은 기간을 선택해 새로 생성하면 현재 Jira 계측값을 포함하는 새 이력을 저장하고 이전 보고서는 그대로 유지합니다. Jira 값이 누락되거나 서로 맞지 않으면 확인 가능한 값만 표시하고, 확인할 수 없는 시간을 0시간으로 대신하지 않습니다.

상태별 시간은 **해결시간 SLA 기준**입니다. Jira에 설정된 SLA 업무시간·휴일·일시정지 규칙을 반영하며, 한국 공휴일을 화면에서 임의로 차감하지 않습니다. 닫힘과 SLA 일시정지 상태인 결과 대기 중·자료 요청 중·보류 중은 시간 목록과 막대에서 제외하고, 나머지 SLA 시간의 합을 100%로 한 누적 막대에서 상태명과 비율을 봅니다. 현재 상태나 위반 당시 상태가 해당 상태인 경우에는 배지를 계속 표시합니다. 마우스를 올리면 상태명·SLA 시간·비율을 확인합니다. 시간이 확인되지 않으면 수치 대신 안내와 경고를 표시합니다. 실제 경과시간만 저장한 이전 보고서는 상태별 수치를 숨기므로 새로 생성해야 SLA 기준 시간을 볼 수 있습니다. 기본 목록의 경과일은 기존처럼 티켓 생성일부터 보고서 생성일까지의 날짜 차이입니다.

## 재배포 현황

매일 08:00 KST에 자동 갱신하고 **지금 갱신**으로도 수집할 수 있습니다. 같은 날 재생성하면 당일 저장본을 대체합니다. 화면은 최신 저장본을 60초마다 조회하며 서버 갱신 실패 시 마지막 데이터와 지연 안내를 표시합니다.

완료는 재배포 Y·라이선스 제외·Closed·해결일 2026-01-01 이후 조건입니다. 현재 진행 중은 생성일에 관계없이 닫히지 않은 재배포 Y 티켓입니다. 전체·완료·진행 중 카드로 범위를 바꾸고 원인·검색을 조합합니다. 월별 막대를 누르면 Jira의 배포 완료 월이 해당 월인 완료 티켓만 표시합니다. 같은 월을 다시 누르거나 해제 칩으로 복귀합니다.

재배포 티켓 표는 통합 검색과 함께 **번호/제목·유형·현재 상태·재배포 원인·재패치·완료 월** 컬럼별 텍스트 검색을 제공합니다. 번호/제목 검색에는 같은 칸의 고객사, 재배포 원인 검색에는 상세 사유도 포함합니다. 입력하면 즉시 반영되고 여러 컬럼의 조건을 모두 만족하는 티켓만 표시합니다. 모바일에서도 같은 컬럼 검색을 사용할 수 있습니다. **초기화**는 통합·컬럼 검색어와 원인·완료 월 선택을 지우고 첫 페이지로 돌아가며, 전체/진행 중/완료 범위는 유지합니다.

배포 완료 월 누락을 해결월로 대신 계산하지 않습니다. 기록된 재패치 횟수는 실제 배포 이벤트 수와 다를 수 있고, 빈 값과 0을 구분합니다. 상세 사유와 담당 정보는 Jira에 입력된 값이며 자동 책임 소재 분석 결과가 아닙니다.

## 전체 이슈와 장기 이슈

**전체 이슈**는 보고서에 포함된 티켓만이 아닌 프로젝트 전체 목록입니다. 첫 조회부터 서버가 백그라운드로 수집하고 조회가 이어지는 동안 최소 30초 간격으로 변경분을 갱신합니다. 화면은 수집 중 2초, 그 외 30초 간격으로 조회합니다. 서버 재시작 후 캐시를 다시 만들고, 삭제된 이슈는 시간별 전체 재동기화 때 반영합니다. 오류가 나면 이전 목록과 오류 상태를 유지합니다.

**장기 이슈**는 최신 일반 보고서의 w7 티켓 집합을 기준으로 현재 Jira 활동과 댓글을 봅니다. SLA 위반 전체 목록과 같지 않습니다. 댓글은 기본 펼침이며 5개부터 더보기마다 최신 10개·15개로 다시 조회합니다. 댓글 조회 실패 시 이전 내용을 유지합니다. 댓글 이미지는 인증된 백엔드를 통해 가져옵니다.

## 히스토리와 관리 기능

대시보드·연간 보고서의 **보고서 히스토리** 버튼으로 일반/연간 목록을, SLA 현황의 같은 버튼으로 SLA 이력 영역을 엽니다. 일반/연간 보고서는 삭제할 수 있지만 SLA 이력에는 삭제 기능이 없습니다. 재배포의 과거 일별 저장본을 조회하는 화면/API는 현재 없습니다.

파트너 관리는 조직·멤버별 이슈, 사이트 관리는 장비·접속 정보·패치·방문 이력을 관리합니다. 파일 보관함에서는 폴더, 이동, 선택 ZIP 다운로드·삭제와 PDF·Word·Excel·Markdown·이미지·텍스트 미리보기를 사용합니다. 일부 문서 형식은 서버의 LibreOffice 변환이 필요합니다.

감사로그는 `SUPERADMIN` 계정으로 작업 기록을 검색·조회하는 화면이며 수정·삭제 기능은 없습니다. 로그인 실패 기록의 계정명은 입력값이지 인증 성공을 뜻하지 않습니다.

데이터 정의·오류 기준은 [SLA 현황](../../backend/docs/08_sla_violation_report.md), [재배포 현황](../../backend/docs/09_redeployment_report.md), 운영 절차는 [운영 가이드](../../backend/docs/10_operations.md)를 참고하세요.
