## 범위와 변경

Domain·Application, API·내보내기·미리보기, 전체 페이지·컴포넌트·훅·상태, 앱 조립·라우터, 스타일·디자인 토큰과 빌드·정적 파일 전달 구성을 검토했습니다. 최종 소스는 TypeScript/TSX 225개, CSS 4개, 디자인 JSON 1개입니다. 의존성 버전과 백엔드는 변경하지 않았습니다.

## 기능 보존과 검증

정렬 동점·누락 날짜·숫자/한국어 순서, 검색 정규화·기간 경계, SLA 필터 적용 대상, 원본 배열·객체, 보고서 집계 정책과 내보내기 전체 행을 유지했습니다. 뉴스 번역과 서버 데이터 변경은 다음 렌더에 반영하며 새로운 데이터 캐시나 TTL 변경은 없습니다. 권한·로그인·폴링·수동 갱신·요청 취소·바이너리 URL 정리의 기존 동작을 유지했습니다.

129개 데이터 조합의 원본 동등성을 확인했습니다. Excel은 긴 본문뿐 아니라 Unicode·줄바꿈·불규칙 행 300개 조합에서 워크북 전체 객체를 비교했습니다. 렌더 회귀 검사는 재사용 횟수와 함께 새 데이터·검색·언어·Jira context·파일 이동 반영 및 열기 취소·실패를 검사합니다. 모든 API adapter와 대형 PDF/Excel 파서의 기존 지연 로딩은 유지했습니다.

기존 전체 테스트 601개에 회귀 검사를 추가하여 Windows(Node 24)와 Linux 컨테이너(Node 22)에서 각각 619개가 모두 통과했습니다. TypeScript 검사, Vite 빌드와 변경 파일 공백 검사도 통과했습니다. 운영 배포에서는 검사한 정적 파일과 실제 응답의 일치 및 백엔드·DB·운영 설정 보존을 확인합니다.
